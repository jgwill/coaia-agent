COAIA-agent repository operating contract

1. Treat tracked project changes as commit-and-push work, not scratch notes.
   - Before finishing a work turn, run `git status --short .` from the repo root.
   - Include staged files and relevant tracked modifications in a coherent commit.
   - Push the commit to `origin` in the same turn unless the user explicitly asks not to push.

2. Bind commits to GitHub issue surfaces in `jgwill/coaia-agent`.
   - Search for an existing issue that matches the change.
   - If none exists, create a concise issue before committing.
   - Reference the issue number in the commit body or subject with `Refs #N` / `Closes #N` as appropriate.
   - Comment on the issue after pushing with the commit SHA and changed paths.

3. Preserve COAIA runtime artifacts deliberately.
   - `.coaia` JSONL/chart/narrative changes are first-class project artifacts when they describe durable structural-tension state, verified handles, or narrative beats.
   - Do not leave `.coaia` changes uncommitted just because they are generated by tools.
   - Secret-scan and sanity-check runtime artifacts before staging.

4. Do not blindly commit local/private scratch material.
   - Inspect untracked paths before staging them.
   - Avoid committing `.env`, local credentials, local TUI state, curator backups, transient resumes, cache folders, or large copied corpora unless an issue explicitly calls for them.
   - If an untracked path is a recurring local artifact, add the appropriate ignore rule or create an issue for a durable import strategy.

5. Expect local integration files to be impacted by upstream pulls.
   - Files such as `Dockerfile`, compose/bootstrap scripts, `.hermes.md`, and local runtime adapters may intentionally diverge from upstream Hermes while COAIA integration matures.
   - When pulling upstream, inspect these files for conflicts or silent overwrites before continuing.
   - Preserve local COAIA additions only when they are issue-linked and still desired; otherwise create a cleanup issue instead of leaving drift ambiguous.

6. Keep the loop autonomous and verifiable.
   - Prefer automation hooks/scripts that enforce status checks, issue linkage, secret scanning, and push verification over relying on memory.
   - Final responses should include issue URL, commit SHA, push status, and any deliberately uncommitted paths.
